# 티어 평가 서비스 PRD (Milestone 1)

작성일: 2026-10-28 · 상태: 초안 (승인 대기)
관련 문서: [TECH.md](TECH.md) (M1 기술 방식) · [next-features/](next-features/README.md) (M1 이후 feature별 문서)

이 문서는 **Milestone 1(M1)만** 다룬다. M1 이후의 확장은 `next-features/`에 feature별로 따로 정의한다.

## 1. 배경 / 목적

평가 대상자 리스트가 있을 때, **평가 기준별로 S/A/B/C 티어를 매기고**, 티어를 점수로 환산해 **최종 점수와 순위**를 내는 서비스.

### 만들려는 것

대상자 목록과 평가 기준을 입력하면, 기준마다 대상자를 S/A/B/C 티어로 나누고 그 결과를 점수·순위로 보여주는 서비스다. 새로 만든다. **정적 웹 → DB 연동 웹 → Android 앱 → 멀티플랫폼 전환 검토** 순서로 키우고, 이 문서는 첫 단계인 M1만 다룬다.

핵심 경험은 다음과 같다.

- 대상자와 기준은 사용자가 자유롭게 입력한다.
- 자주 쓰는 구성은 **preset**으로 골라 불러올 수 있고, 불러온 뒤에도 자유롭게 바꿀 수 있다.
- 기준별 화면에서 대상자 칩을 S/A/B/C 행으로 드래그해 티어를 매기고, 미배치 칩은 별도 풀에 둔다.
- 티어를 점수로 환산해 총점과 순위를 낸다. 티어별 점수는 기준마다 설정할 수 있다.
- 평가 정보는 JSON으로 가져오기/내보내기 할 수 있고, JSON을 직접 수정해서 다시 가져올 수도 있다.
- 배치는 브라우저에 자동 저장된다.

M1은 위 경험을 서버 없이 정적 웹으로 완성한다. 티어 설명 등 나머지는 M1 이후 feature로 뺀다.

## 2. 진행 원칙과 M1 이후

- feature마다 "해결할 문제"를 먼저 정의하고, 완료 기준으로 그 문제가 실제로 풀렸는지 확인한 뒤에만 다음으로 넘어간다.
- 한 번에 여러 feature를 섞지 않는다.
- **M1 → next feature**: M1을 끝내고 실제 평가를 한 번 치러본 뒤, 가장 큰 불편에 맞는 feature를 고른다. 각 feature는 선행 feature가 끝나야 시작할 수 있다.

M1 이후 feature 목록과 선행 관계는 [next-features/README.md](next-features/README.md)에 있다.

**용어**
- **대상자**: 평가받는 쪽.
- **기준**: 평가 항목.
- **배치**: 한 기준에서 한 대상자에 매긴 티어 (S/A/B/C).
- **평가자**: 배치를 하는 사람.

**안티골 (M1 포함 전체)**
- 배치한 결과가 새로고침 후 사라지는 것.
- 미배치 상태에서 순위가 나와 잘못된 결과를 믿게 되는 것.
- 점수·순위 규칙이 화면 코드에 얽혀서 서버나 앱으로 옮길 때 다시 짜야 하는 구조.
- 이후 feature 때문에 앞서 저장한 데이터가 못 열리게 되는 것.

## 3. M1. 기본 티어 평가

**상태**: 정적 웹 · 평가자 1명

### 문제
대상자 여러 명을 여러 기준으로 평가할 때, 기준별로 티어를 매기는 것까지는 직관적이지만 그 결과를 점수와 순위로 모으고, 빠뜨린 배치가 없는지 확인하는 일은 손으로 해야 한다. 기준마다 중요도가 달라도 같은 점수표로만 계산하면 이를 반영할 수 없다. 평가 정보를 다른 평가에 다시 쓰거나 백업하기도 어렵다.

### 목표 / 비목표
- 목표: 설정 → 평가 → 결과 흐름을 GitHub Pages에서 끝까지 수행. preset 선택과 JSON 가져오기/내보내기 제공. 점수·순위·잠금 규칙을 화면과 분리.
- 비목표: 여러 평가자 합산, 로그인, 서버/DB, 티어 내 가중치, 기준별 가중치(배수), 티어 설명. (모두 next feature, 아래 §2 링크)

### 사용자
평가자 1명이 혼자 쓴다. 설정 편집과 평가가 한 앱에 공존하며 관리자/일반 구분이 없다.

### 규칙
- **기본 점수표**: S=4, A=3, B=2, C=1 *(기획자 제안, 확정 필요)*.
- **기준별 점수표**: 기준마다 S/A/B/C 점수를 따로 설정할 수 있다. 설정하지 않은 기준은 기본 점수표를 쓴다.
- **점수표 검증**: 점수는 0 이상의 숫자이고 S > A > B > C 순서여야 한다. 어기면 저장하지 않고 오류를 보여준다.
- **총점**: 각 기준에서 그 기준의 점수표로 환산한 점수의 합.
- **순위**: 총점 내림차순. 동점이면 S 개수가 많은 쪽 우선. S 개수까지 같으면 공동 순위 (1, 1, 3 방식).
- **결과 잠금**: 모든 (기준 × 대상자)가 배치돼야 결과 확인 가능. 미배치가 있으면 결과 화면에 잠금 안내와 남은 건수 표시.

### 화면 / 기능
**설정 페이지**
- **Preset 선택**: 목록에서 preset을 고르면 대상자와 기준이 그 구성으로 채워진다. 기본 제공: 샘플(가상 데이터), 빈 구성. 기존 데이터가 있으면 교체 확인 대화상자를 거치고, 교체하면 기존 배치는 초기화된다.
- preset을 불러온 뒤에는 일반 입력과 똑같이 자유롭게 수정할 수 있다 (preset 원본은 바뀌지 않는다).
- 대상자 추가/삭제/이름 수정.
- 기준 추가/삭제/이름 수정/순서 변경.
- 기준마다 S/A/B/C 점수 입력 (비워 두면 기본 점수표 사용). 기본 점수표로 되돌리는 버튼.
- CSV(또는 줄바꿈 구분) 붙여넣기로 대상자·기준 일괄 등록.
- 삭제 시 해당 항목의 배치도 함께 삭제 (확인 대화상자).
- **JSON 내보내기**: 평가 정보(대상자, 기준, 기준별 점수표, 배치)를 JSON 파일로 저장.
- **JSON 가져오기**: JSON 파일을 불러와 현재 데이터를 교체 (확인 대화상자). 파일을 직접 수정해서 가져와도 된다. 형식이 틀리면 어디가 문제인지 알려주고 기존 데이터는 그대로 둔다.

**평가 페이지**
- 기준별 탭. 선택한 기준에서 S/A/B/C 행 + 미배치 풀.
- 대상자 칩을 드래그해 티어에 배치, 풀로 되돌리기 (칩의 × 버튼으로도 풀로 되돌릴 수 있다).
- 기준별 진행률(배치/전체) 표시. 변경 즉시 자동 저장.

**결과 페이지**
- 순위, 대상자, 기준별 티어, 총점, S 개수. 기준별 점수표가 적용된 총점을 보여준다.
- 미배치가 남아 있으면 잠금 안내 + 평가 페이지로 이동 링크.

**공통**
- 한국어 UI. 상단 내비게이션으로 3개 페이지 이동.
- 데이터 초기화 버튼 (확인 대화상자).
- 대상자·기준 이름을 바꿔도 기존 배치가 유지된다.

### 완료 기준
- GitHub Pages URL에서 샘플 preset을 불러와 평가를 끝내고 순위를 본다. 대상자 20개 × 기준 6개 규모에서도 불편 없이 동작한다.
- preset을 불러온 뒤 대상자·기준을 추가/삭제/수정해도 정상 동작한다. 빈 구성에서 직접 입력해도 같은 흐름이 동작한다.
- 새로고침·브라우저 재시작 후에도 배치가 유지된다.
- 기준별로 다른 점수표를 설정하면 총점·순위가 그 점수표대로 계산되고, 점수표를 설정하지 않은 기준은 기본 점수표를 쓴다. 순서가 어긋난 점수표는 저장되지 않는다.
- 내보낸 JSON을 가져오면 같은 결과가 나온다(점수표 포함). 직접 수정한 JSON도 가져와지고, 잘못된 JSON은 기존 데이터를 건드리지 않고 오류를 보여준다.
- 점수 계산과 순위 로직에 동점·공동 순위·잠금 케이스를 검증하는 최소 자동 점검이 있다.

### M1 이후로 넘어가는 조건
실제 평가 한 번을 이 사이트로 치러보고 가장 큰 불편이 무엇인지 확인한다. 그 불편이 next feature 중 어느 문제와 맞는지로 다음 feature를 정한다.

### 기획자 판단 (확인 필요)
- 기본 점수표 S=4/A=3/B=2/C=1.
- 점수는 소수 허용, 음수 불가. 기준 간 점수표 복사 같은 편의 기능은 M1에서 제외.
- S 개수까지 같을 때 공동 순위.
- 삭제 시 배치 동반 삭제, 초기화 버튼 포함, 기준 순서 변경 포함.
- JSON 내보내기/가져오기 범위: 설정(대상자·기준)과 배치를 한 파일로 다룬다. 설정만 따로 내보내는 템플릿 기능은 두지 않는다.
- 가져오기는 병합이 아니라 교체로 한다.
- preset은 앱에 내장된 목록에서 고른다 (샘플, 빈 구성). 사용자가 자기 preset을 저장하는 기능은 M1에서 두지 않고, JSON 내보내기/가져오기로 대신한다. 저장 기능이 필요하면 next feature로 뺀다.
- preset은 대상자와 기준만 담고 배치는 담지 않는다.
- 시각 디자인은 다크 테마와 S/A/B/C 구분 색상(S 빨강, A 주황, B 노랑, C 연두)을 권장.
