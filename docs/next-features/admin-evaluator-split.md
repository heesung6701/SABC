# Feature: 관리(CMS) / 평가(일반) 화면 분리 (admin-evaluator-split)

**단계**: DB 연동 웹 · **선행**: [server-multi-evaluator](server-multi-evaluator.md)

## 문제
다중 평가자가 생긴 뒤에도 설정(대상자·기준·점수·루브릭)을 누구나 수정할 수 있어서, 평가 도중 기준이 바뀌거나 실수로 지워질 수 있다.

## 목표 / 비목표
- 목표: 편집은 관리자만, 평가자는 읽기 전용 설정 + 평가 화면만 접근.
- 비목표: 세분화된 권한(여러 단계의 관리자), 변경 이력 조회.

## 요구사항
- 역할 두 가지: 관리자, 평가자.
- 관리자: 대상자·기준·점수표·루브릭 편집, 평가자 초대/관리.
- 평가자: 설정을 읽기만 가능, 평가와 결과 확인.
- 화면에서 숨기는 것뿐 아니라 서버가 권한 없는 수정 요청을 거부한다.
- 이미 배치가 있는 대상자·기준의 삭제는 관리자가 확인 후에만 가능 *(기획자 제안)*.

## 완료 기준
- 평가자 계정으로는 설정을 수정할 수 없고, 관리자 계정으로만 수정할 수 있다.
- 평가 중 평가자 화면에서 기준이 바뀌지 않는다.

## 기술 방식
- 역할: 평가 참여자에 `role`(admin / evaluator) 부여.
- 접근 제어: 대상자·기준·점수·루브릭의 쓰기는 RLS에서 admin만 허용. evaluator는 읽기만.
- 화면: M1부터 설정과 평가가 별도 페이지이므로, 설정 페이지를 관리자 영역으로 옮기고 일반 평가자에게는 숨긴다. 화면 숨김만으로는 보안이 아니므로 반드시 서버 정책으로 막는다.

## 테스트
- evaluator 계정으로 설정 변경 요청이 서버에서 거부된다.
- admin 계정은 변경할 수 있다.

## 기획자 판단 / 열린 질문
- 평가가 시작된 뒤(배치가 하나라도 생긴 뒤) 기준·점수 수정을 막을지 경고만 할지.
- 관리자도 평가자를 겸할 수 있게 한다.
